# Бриф проекта: "Моя Полка" (MyShelf)

## 1. Общие сведения

**Название продукта:** Моя Полка (MyShelf)

**Краткое описание:** 
Десктопное приложение для каталогизации и учёта личной библиотеки книг. Программа решает проблему хаотичного хранения информации о прочитанных и планируемых к прочтению книгах, позволяя структурировать коллекцию, отслеживать прогресс чтения и получать наглядную статистику без необходимости подключения к интернету.

**Целевая аудитория:** 
Книголюбы, которые хотят вести учёт своей домашней библиотеки локально на своём компьютере, не полагаясь на облачные сервисы, социальные сети (вроде LiveLib) или интернет-соединение.

---

## 2. Функциональные требования

### Обязательные (MVP)
1. Пользователь может **добавить новую книгу** в коллекцию, указав название, год издания, оценку, статус чтения, а также привязав к ней авторов и жанры.
2. Пользователь может **просматривать список** всех книг в виде таблицы с основной информацией (название, автор, год, жанр, статус, оценка).
3. Пользователь может **редактировать или удалять** существующие книги в коллекции.
4. Пользователь может **фильтровать** список книг по статусу чтения («Хочу прочитать», «Читаю сейчас», «Прочитано») и **сортировать** по году издания или оценке.
5. Пользователь может **искать** книги по названию или автору (частичное совпадение).
6. Пользователь может **просматривать аналитику**: общее количество книг, средняя оценка прочитанных книг и распределение по статусам чтения.

### Дополнительные (при наличии времени)
1. Пользователь может **экспортировать** текущий список книг в файл формата CSV.
2. Пользователь может **добавлять текстовый комментарий** или личную рецензию к книге (впечатления, цитаты).
3. Пользователь может **управлять справочниками** (добавлять новых авторов или жанры) через отдельное окно настроек, не создавая их "на лету" при добавлении книги.

---

## 3. Нефункциональные требования

- **Язык интерфейса:** Русский.
- **Производительность:** Время отклика интерфейса при стандартных операциях (добавление, фильтрация, поиск) — не более 1 секунды.
- **Хранение данных:** Локально в файле базы данных SQLite (`collection.db`). Сетевые запросы и использование интернета полностью исключены.
- **Защита от ошибок:** 
  - Нельзя сохранить книгу без названия (поле обязательно для заполнения).
  - Оценка должна быть числом в допустимом диапазоне (например, от 1 до 10).
  - При попытке удаления книги должно появляться диалоговое окно с подтверждением действия.
- **Инициализация БД:** При первом запуске приложение автоматически проверяет наличие файла БД и, если его нет, создаёт его и все необходимые таблицы из встроенного SQL-скрипта.

### Обоснование нормализации:
База данных приведена к Третьей нормальной форме (3НФ). 
- Справочники `authors` (авторы книг), `genres` (литературные жанры) и `statuses` (статусы чтения) вынесены в отдельные таблицы, чтобы избежать дублирования строк и проблем с опечатками (например, "Фантастика" и "фантастика").
- Связи Many-to-Many (`item_authors`, `item_genres`) реализованы через промежуточные таблицы, что позволяет одной книге иметь нескольких авторов (соавторство) и несколько жанров, не нарушая целостности данных.

## 6. Сценарии использования (Use Cases)

### Сценарий 1: Добавление новой книги (MVP-1)
- **Актёр:** Пользователь
- **Предусловие:** Приложение запущено, открыт главный экран.
- **Основной поток:**
  1. Пользователь нажимает кнопку "Добавить книгу".
  2. Система открывает форму добавления.
  3. Пользователь вводит название книги, год издания, оценку, выбирает статус, авторов и жанры.
  4. Пользователь нажимает кнопку "Сохранить".
  5. Система проверяет данные, сохраняет книгу и обновляет список на главном экране.
- **Альтернативный поток:**
  - 3а. Пользователь не ввёл название и нажал "Сохранить".
  - 4а. Система выводит сообщение: "Поле 'Название' обязательно для заполнения" и не закрывает форму.

### Сценарий 2: Просмотр списка всех книг (MVP-2)
- **Актёр:** Пользователь
- **Предусловие:** В библиотеке есть хотя бы одна сохранённая книга.
- **Основной поток:**
  1. Пользователь открывает приложение.
  2. Система отображает таблицу со всеми книгами: название, автор, год, жанр, статус, оценка.
  3. Пользователь просматривает список, при необходимости прокручивая его.

### Сценарий 3: Редактирование и удаление книги (MVP-3)
- **Актёр:** Пользователь
- **Предусловие:** В списке есть хотя бы одна книга.
- **Основной поток (редактирование):**
  1. Пользователь выбирает книгу в списке и нажимает "Редактировать".
  2. Система открывает форму с текущими данными книги.
  3. Пользователь изменяет нужные поля и нажимает "Сохранить".
  4. Система обновляет информацию о книге и отображает изменения в списке.
- **Основной поток (удаление):**
  1. Пользователь выбирает книгу и нажимает "Удалить".
  2. Система показывает окно подтверждения: "Вы уверены, что хотите удалить эту книгу?".
  3. Пользователь нажимает "Да".
  4. Система удаляет книгу и обновляет список.
- **Альтернативный поток:**
  - 3а. Пользователь нажимает "Отмена" в окне подтверждения.
  - 4а. Система закрывает окно, книга остаётся в списке.

### Сценарий 4: Фильтрация и сортировка списка (MVP-4)
- **Актёр:** Пользователь
- **Предусловие:** В библиотеке есть книги с разными статусами, годами и оценками.
- **Основной поток (фильтрация):**
  1. Пользователь выбирает в фильтре статус, например, "Прочитано".
  2. Система показывает только книги с выбранным статусом.
- **Основной поток (сортировка):**
  1. Пользователь нажимает на заголовок столбца "Год" или "Оценка".
  2. Система перестраивает список по возрастанию или убыванию выбранного поля.
- **Альтернативный поток:**
  - 1а. Пользователь выбирает фильтр "Все статусы".
  - 2а. Система возвращает полный список книг.

### Сценарий 5: Поиск по названию или автору (MVP-5)
- **Актёр:** Пользователь
- **Предусловие:** В библиотеке есть несколько книг.
- **Основной поток:**
  1. Пользователь вводит часть названия или имя автора в поле поиска (например, "Достоевский").
  2. Система мгновенно показывает только совпадающие книги.
  3. Пользователь просматривает результаты.
- **Альтернативный поток:**
  - 1а. Пользователь вводит запрос, по которому нет совпадений.
  - 2а. Система показывает пустой список и сообщение "Ничего не найдено".

### Сценарий 6: Просмотр аналитики (MVP-6)
- **Актёр:** Пользователь
- **Предусловие:** В базе данных есть сохранённые книги.
- **Основной поток:**
  1. Пользователь нажимает кнопку "Статистика" на главном экране.
  2. Система открывает экран аналитики.
  3. Система отображает: общее количество книг, среднюю оценку прочитанных книг и диаграмму распределения по статусам.
  4. Пользователь изучает статистику и нажимает "Назад".
- **Альтернативный поток:**
  - 3а. В библиотеке пока нет ни одной книги.
  - 4а. Система отображает нулевые значения и сообщение "Добавьте первую книгу, чтобы увидеть статистику".

### Сценарий 7: Экспорт списка в CSV (Доп-1)
- **Актёр:** Пользователь
- **Предусловие:** В библиотеке есть хотя бы одна книга.
- **Основной поток:**
  1. Пользователь нажимает кнопку "Экспорт в CSV".
  2. Система предлагает выбрать место для сохранения файла.
  3. Пользователь указывает папку и имя файла.
  4. Система сохраняет файл в формате CSV со списком всех книг.
- **Альтернативный поток:**
  - 3а. Пользователь отменяет выбор папки.
  - 4а. Система не создаёт файл и возвращается к главному экрану.

### Сценарий 8: Добавление комментария к книге (Доп-2)
- **Актёр:** Пользователь
- **Предусловие:** В библиотеке есть хотя бы одна книга.
- **Основной поток:**
  1. Пользователь открывает карточку книги и переходит в раздел "Комментарий".
  2. Пользователь вводит текст рецензии или заметки.
  3. Пользователь нажимает "Сохранить".
  4. Система сохраняет комментарий и отображает его в карточке книги.
- **Альтернативный поток:**
  - 2а. Пользователь оставляет поле пустым и нажимает "Сохранить".
  - 3а. Система сохраняет пустой комментарий или показывает подсказку.

### Сценарий 9: Управление справочниками (Доп-3)
- **Актёр:** Пользователь
- **Предусловие:** Приложение запущено.
- **Основной поток:**
  1. Пользователь открывает раздел "Настройки" → "Справочники".
  2. Пользователь выбирает вкладку "Авторы" или "Жанры".
  3. Пользователь нажимает "Добавить" и вводит новое имя автора или жанр.
  4. Система сохраняет запись, и она становится доступной при добавлении книг.
- **Альтернативный поток:**
  - 3а. Пользователь вводит уже существующее название.
  - 4а. Система показывает сообщение "Такой автор/жанр уже существует" и не создаёт дубликат.

## 7. Критерии приёмки

- [ ] Приложение запускается и корректно работает.
- [ ] При первом запуске автоматически создаётся файл БД SQLite и все таблицы согласно модели.
- [ ] Реализовано добавление новой книги с привязкой к статусу чтения, жанру и автору (в том числе нескольким).
- [ ] Реализовано редактирование и удаление существующей книги (с подтверждением удаления).
- [ ] Работает валидация: невозможно сохранить книгу без названия или с некорректной оценкой.
- [ ] Работает поиск по названию и автору (частичное совпадение, регистронезависимый).
- [ ] Работает фильтрация списка по статусу чтения и сортировка по году/оценке.
- [ ] Экран статистики корректно отображает общее количество книг в библиотеке.
- [ ] Экран статистики корректно рассчитывает среднюю оценку прочитанных книг.
- [ ] Весь пользовательский интерфейс выполнен на русском языке.
- [ ] Время отклика на все базовые операции (клики, ввод) не превышает 1 секунды.
