# Тест-план приложения "Моя Полка" (MyShelf)

## 1. Объект тестирования

Десктопное приложение **"Моя Полка"** — локальный каталогизатор личной библиотеки книг на Python + SQLite. Позволяет добавлять, редактировать, удалять книги, фильтровать и искать их, а также просматривать статистику коллекции. Приложение работает полностью офлайн, данные хранятся в файле `collection.db`.

## 2. Цели тестирования

- Убедиться, что **все функции из брифа работают корректно** (CRUD, поиск, фильтрация, аналитика, экспорт).
- Проверить **устойчивость к некорректному вводу** (пустые поля, недопустимые значения, SQL-инъекции).
- Проверить **целостность данных** в БД (связи M:N, каскадное удаление, отсутствие дубликатов).
- Убедиться, что приложение **сохраняет данные между запусками**.
- Оценить **удобство интерфейса** по макетам Figma.
- Проверить **производительность** базовых операций (не более 1 секунды).

## 3. Области тестирования

### 3.1. Функциональное тестирование
Проверка всех операций из брифа:
- Добавление, редактирование, удаление книг.
- Привязка жанров и авторов (M:N связи).
- Поиск по названию/автору.
- Фильтрация по статусу, сортировка по году/оценке.
- Расчёт аналитики (количество, средняя оценка, распределение).
- Экспорт в CSV/JSON.

### 3.2. Тестирование интерфейса (по макетам)
- Соответствие UI макетам Figma.
- Читаемость текста, цветовое кодирование статусов.
- Понятность сообщений об ошибках.
- Логика переходов между экранами.

### 3.3. Тестирование устойчивости к ошибкам
- Ввод пустых строк, спецсимволов, SQL-инъекций.
- Отрицательные числа, значения вне диапазона.
- Удаление несуществующих записей.
- Повторное добавление дубликатов в справочниках.

### 3.4. Тестирование производительности
- Время отклика на поиск в коллекции 100+ книг.
- Скорость инициализации БД при первом запуске.
- Скорость расчёта аналитики.

### 3.5. Тестирование целостности данных
- Корректность связей M:N (одна книга — несколько жанров/авторов).
- Каскадное удаление связей при удалении книги.
- Уникальность имён в справочниках (statuses, genres, authors).
- Сохранение данных после перезапуска приложения.

## 4. Уровни критичности дефектов

| Уровень | Описание | Пример |
|---------|----------|--------|
| **Критический** | Приложение падает, данные теряются, функция полностью неработоспособна. | Падение при сохранении книги, потеря всех записей после перезапуска. |
| **Значительный** | Функция работает, но с существенными ошибками, обходные пути сложны. | Неправильный расчёт средней оценки, не удаляются связи M:N. |
| **Незначительный** | Функция работает, но есть мелкие недочёты. | Неудачное форматирование даты, опечатка в сообщении. |
| **Рекомендация** | Не ошибка, но можно улучшить UX. | Добавить подсказку при первом запуске. |

- [x] Готовы макеты UI в Figma.
- [ ] Реализован графический интерфейс (для UI-тестов).

## 6. Критерии завершения тестирования

Тестирование считается завершённым, когда:
- [ ] Выполнены **100% тест-кейсов** из TEST_CASES.md.
- [ ] Устранены **все критические и значительные дефекты**.
- [ ] Незначительные дефекты задокументированы и оценены.
- [ ] Проведено регрессионное тестирование после исправлений.
- [ ] Подготовлен отчёт о тестировании.
